# Nautilus.CIM - Интерактивный прототип

## Описание

Кликабельный прототип платформы Nautilus.CIM для создания, редактирования и управления
профилями информационных моделей электроэнергетических систем по стандарту CIM.

## Структура файлов

```
NauCIM/
├── index.html                  # Главная страница
├── projects.html               # Управление проектами
├── profile-editor.html         # Редактор профилей
├── project-details.html        # Редактор проекта
├── compare.html                # Сравнение профилей
├── src/
│   ├── app/
│   │   ├── pages/           #  js модули страницы.  контроллер страницы
│   ├── services/              # Бизнес-логика и операции с данными
│   │   ├── dataloader.js     # ⭐ Загрузка данных в MemoryStore
│   │   ├── model-service.js
│   │   ├── profile-service.js
│   │   └── project-service.js
│   ├── store/
│   │   └── memory-store.js   # ⭐ Хранилище данных в памяти
│   ├── ui/
│   │   ├── components/       # Переиспользуемые компоненты (модалки)
│   │   ├── renderers/        # Модули рендеринга
│   │   └── sidebar/          # ⭐ Компоненты сайдбара
│   └── styles/                # ⭐ Все CSS файлы
├── docs/                       # Документация
│   ├── ARCHITECTURE.md        # Описание архитектуры
│   ├── CONVENTIONS.md         # Соглашения о разработке
│   └── DATA_STRUCTURES.md  # Контракт данных
├── data.js                     # ⚠️ УСТАРЕЛО - не использовать
├── sidebar.js                  # ⚠️ УСТАРЕЛО - не использовать
├── styles.css                  # ⚠️ УСТАРЕЛО - не использовать
└── README.md                   # Инструкция
```

### ⚠️ Устаревшие файлы (не использовать для новой разработки)

- **`data.js`** - заменен на `src/services/dataloader.js` и `src/services/*-service.js`
- **`sidebar.js`** - заменен на `src/ui/sidebar/*`
- **`styles.css`** - заменен на `src/styles/**`

Эти файлы сохранены только для совместимости. Вся новая разработка должна использовать модульную архитектуру в директории `src/`.

## Как использовать

⚠️ **ВАЖНО**: Приложение требует локальный HTTP-сервер для работы (из-за использования `fetch()` для загрузки JSON).

### Быстрый старт

1. Откройте терминал в папке проекта
2. Запустите локальный сервер:
   ```bash
   python -m http.server 8000
   ```
   Или на некоторых системах:
   ```bash
   python3 -m http.server 8000
   ```
3. Откройте браузер по адресу:
   ```
   http://localhost:8000
   ```

Подробные инструкции см. в [docs/RUN_LOCAL.md](docs/RUN_LOCAL.md)

### Страницы приложения

- **Главная** (`index.html`) → `src/app/pages/index-page.js` - Дашборд, последние проекты
- **Проекты** (`projects.html`) → `src/app/pages/projects-page.js` - Управление проектами
- **Редактирование проекта** (`project-details.html`) → `src/app/pages/project-details-page.js` - Модели, профили, классы
- **Сравнение** (`compare.html`) - Сравнение профилей
- **Редактор профилей** (`profile-editor.html`) - Визуальный редактор с диаграммами

## Примечания

- Приложение загружает демо-данные из JSON-файлов в папке `models-data/`
- UI-состояние сохраняется в localStorage браузера
- Для полноценной работы требуется современный браузер с поддержкой ES6+
- **Требуется локальный HTTP-сервер** - не открывайте `index.html` напрямую в браузере

# Nautilus.CIM v2.0 - Интерактивный прототип с редактором диаграмм

## 🎉 Новые возможности

### 📐 Редактор диаграмм классов (diagram.html)

**Полнофункциональный визуальный редактор для создания UML-диаграмм классов:**

- ✅ **Drag-and-drop** - перетаскивайте классы из левой панели на холст
- ✅ **Два типа связей:**
  - ◁ **Наследование** (обобщение) - полая треугольная стрелка
  - → **Ассоциация** - простая стрелка
- ✅ **Интерактивное редактирование:**
  - Перемещение классов с автоматическим обновлением связей
  - 4 точки соединения на каждом классе (сверху, снизу, слева, справа)
  - Удаление классов через кнопку ×
- ✅ **Сеточный холст** для точного позиционирования
- ✅ **Панорамирование** средней кнопкой мыши
- ✅ **Сохранение** диаграмм в localStorage

## Примеры использования

### Создание иерархии классов

1. Добавьте родительский класс (например, `IdentifiedObject`)
2. Добавьте дочерние классы (например, `PowerSystemResource`, `AssetInfo`)
3. Переключитесь в режим **◁ Наследование**
4. Соедините дочерние классы с родительским
5. Получится классическая UML-иерархия с полыми стрелками

### Создание ассоциаций

1. Добавьте два связанных класса
2. Переключитесь в режим **→ Ассоциация**
3. Соедините классы
4. Простая стрелка покажет направление ассоциации
